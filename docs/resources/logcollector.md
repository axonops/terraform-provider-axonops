# axonops_logcollector (Resource)

~> **Note:** Log collectors are only supported on **on-prem** deployments. This resource is not available when using AxonOps SaaS.

Manages a log collector configuration for a cluster.

## Example Usage

```terraform
# Kafka server log collector
resource "axonops_logcollector" "server_log" {
  cluster_name          = "my-kafka-cluster"
  name                  = "Kafka Server Log"
  filename              = "/var/log/kafka/server.log"
  date_format           = "yyyy-MM-dd HH:mm:ss,SSS"
  supported_agent_types = ["broker", "kraft-broker"]
}

# Kafka controller log collector
resource "axonops_logcollector" "controller_log" {
  cluster_name          = "my-kafka-cluster"
  name                  = "Kafka Controller Log"
  filename              = "/var/log/kafka/controller.log"
  date_format           = "yyyy-MM-dd HH:mm:ss,SSS"
  supported_agent_types = ["kraft-controller"]
}

# Schema Registry log collector
resource "axonops_logcollector" "schema_registry_log" {
  cluster_name          = "my-kafka-cluster"
  name                  = "Schema Registry Log"
  filename              = "/var/log/schema-registry/schema-registry.log"
  date_format           = "yyyy-MM-dd HH:mm:ss,SSS"
  supported_agent_types = ["schema-registry"]
}

# AxonOps agent log collector
resource "axonops_logcollector" "agent_log" {
  cluster_name          = "my-kafka-cluster"
  name                  = "AxonOps Agent Log"
  filename              = "/var/log/axonops/axon-agent.log"
  date_format           = "yyyy-MM-ddTHH:mm:ssZ"
  supported_agent_types = ["all"]
}

# Custom application log with regex patterns
resource "axonops_logcollector" "app_log" {
  cluster_name          = "my-kafka-cluster"
  name                  = "Custom Application Log"
  filename              = "/var/log/myapp/application.log"
  date_format           = "yyyy-MM-dd HH:mm:ss,SSS"
  info_regex            = "\\[INFO\\]"
  warning_regex         = "\\[WARN\\]"
  error_regex           = "\\[ERROR\\]"
  debug_regex           = "\\[DEBUG\\]"
  error_alert_threshold = 10
  supported_agent_types = ["broker", "kraft-broker"]
}

# Kafka Connect log collector
resource "axonops_logcollector" "connect_log" {
  cluster_name          = "my-kafka-cluster"
  name                  = "Kafka Connect Log"
  filename              = "/var/log/kafka-connect/connect.log"
  date_format           = "yyyy-MM-dd HH:mm:ss,SSS"
  supported_agent_types = ["all"]
}

# GC log collector
resource "axonops_logcollector" "gc_log" {
  cluster_name          = "my-kafka-cluster"
  name                  = "Kafka GC Log"
  filename              = "/var/log/kafka/kafka-gc.log"
  date_format           = "yyyy-MM-ddTHH:mm:ss"
  supported_agent_types = ["broker", "kraft-broker", "kraft-controller"]
}
```

> **Note:** Healthchecks and log collectors for a given cluster share a single document on the AxonOps server. The provider serializes writes to that document across all healthcheck/log-collector resources for the same `cluster_type`/`cluster_name` within one `terraform apply`, so concurrent Terraform operations in the same run cannot silently overwrite each other's changes. This protection does NOT extend across separate `terraform apply` processes (e.g. two CI pipelines applying at once) or edits made via the AxonOps UI at the same time — those can still race and the last write wins.

## Schema

### Required

- `cluster_name` (String) The name of the cluster.
- `filename` (String) The log file path. Supports Go templating (e.g., {{index . "comp_jvm_kafka.logs.dir"}}/server.log).
- `name` (String) The name of the log collector.

### Optional

- `cluster_type` (String) The type of cluster (e.g., cassandra, kafka, dse). Defaults to cassandra.
- `date_format` (String) The date format used in log entries. Default: yyyy-MM-dd HH:mm:ss,SSS
- `debug_regex` (String) Regex pattern for DEBUG level log entries.
- `error_alert_threshold` (Number) Threshold for error alerts. Default: 0
- `error_regex` (String) Regex pattern for ERROR level log entries.
- `info_regex` (String) Regex pattern for INFO level log entries.
- `interval` (String) Interval for log collection. Default: 5s
- `readonly` (Boolean) Whether the log collector is read-only. Default: false
- `supported_agent_types` (List of String) List of agent types this collector supports (e.g., all, broker, kraft-broker, kraft-controller, zookeeper, schema-registry).
- `timeout` (String) Timeout for log collection. Default: 1m
- `warning_regex` (String) Regex pattern for WARNING level log entries.

### Read-Only

- `uuid` (String) The unique identifier for the log collector (auto-generated).

## Import

Log collectors can be imported using the format `cluster_type/cluster_name/filename`:

```shell
# The filename field on the API is "/var/log/kafka/server.log" (leading slash).
# The import ID is cluster_type/cluster_name/filename, so the filename segment
# reproduces that leading slash as a double slash after cluster_name.
terraform import axonops_logcollector.server_log "kafka/my-kafka-cluster//var/log/kafka/server.log"
```

Where:
- `cluster_type` - The type of cluster (cassandra, kafka, or dse)
- `cluster_name` - The name of the cluster
- `filename` - The `filename` attribute of the log collector (not its `name`). The filename may itself contain `/`; everything after `cluster_name` is joined back together and used as-is.

> **Warning:** The import ID identifies the collector by its `filename` attribute, not by `name`. Because `filename` is almost always an absolute path (e.g. `/var/log/kafka/server.log`), the import ID contains a double slash after `cluster_name` — see the example.
