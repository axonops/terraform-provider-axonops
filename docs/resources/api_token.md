# axonops_api_token (Resource)

Manages an AxonOps API token for the provider's organisation. Tokens are immutable: changing allowed_roles, expires_at or rotation_triggers creates a new token and revokes the old one. Requires a superuser API key.

## Example Usage

```terraform
# Read-only token for one Kafka cluster, used by a CI pipeline
resource "axonops_api_token" "ci_readonly" {
  name          = "ci-readonly"
  allowed_roles = ["my-org/kafka/my-kafka-cluster/readonly"]
  expires_at    = "2027-01-01T00:00:00Z"
}

# Admin token rotated every 90 days (requires the hashicorp/time provider)
resource "time_rotating" "admin_token" {
  rotation_days = 90
}

resource "axonops_api_token" "automation" {
  name          = "automation"
  allowed_roles = ["my-org/cassandra/admin", "my-org/kafka/admin"]

  rotation_triggers = {
    rotated_at = time_rotating.admin_token.id
  }

  # Create the new token before the old one is revoked.
  lifecycle {
    create_before_destroy = true
  }
}

output "automation_token" {
  value     = axonops_api_token.automation.secret
  sensitive = true
}
```

## Roles

Each `allowed_roles` entry scopes one role:

| Format | Example | Scope |
|--------|---------|-------|
| `<org>/<role>` | `my-org/readonly` | Every cluster of the organisation |
| `<org>/<cluster_type>/<role>` | `my-org/kafka/admin` | Every cluster of one type |
| `<org>/<cluster_type>/<cluster_name>/<role>` | `my-org/kafka/prod/readonly` | One cluster |

`<role>` is `superuser`, `admin`, `readonly` or `backupadmin`.

## Rotation

AxonOps tokens cannot be changed or rotated in place. Changing `allowed_roles`, `expires_at` or `rotation_triggers` replaces the token: Terraform creates a new token and revokes the old one. Use `create_before_destroy` so the new secret exists before the old one stops working, and change `rotation_triggers` (for example from a `time_rotating` resource) to rotate on a schedule.

## Secret handling

- `secret` is returned by AxonOps only when the token is created. It is stored in Terraform state, so protect the state (remote backend with encryption and access control).
- Clients send it as the header `Authorization: AxonApi <secret>`.
- `name` is kept in Terraform state only; AxonOps does not store token names.
- Managing tokens requires a provider `api_key` with the `superuser` role.

## Schema

### Required

- `allowed_roles` (List of String) Role scopes granted to the token. Each entry is `<org>/<role>`, `<org>/<cluster_type>/<role>` or `<org>/<cluster_type>/<cluster_name>/<role>`, where role is superuser, admin, readonly or backupadmin.
- `name` (String) A label for the token. AxonOps does not store token names, so this value is kept in Terraform state only and can change without replacing the token.

### Optional

- `expires_at` (String) Expiry time in RFC 3339 format (e.g. 2027-01-01T00:00:00Z). Omit for a token that never expires.
- `rotation_triggers` (Map of String) Arbitrary values that force a new token when changed. Use it to rotate the token, for example with a `time_rotating` resource. Combine with `create_before_destroy`.

### Read-Only

- `created_at` (String) Creation time in RFC 3339 format.
- `id` (String) The token key ID assigned by AxonOps.
- `secret` (String, Sensitive) The token secret. AxonOps returns it only when the token is created, so it is null for imported tokens. Send it as `Authorization: AxonApi <secret>`.

## Import

API tokens can be imported using the token key ID:

```shell
terraform import axonops_api_token.ci_readonly 6c0e8f5a-2b1d-4e7f-9a3c-1d2e3f4a5b6c
```

In Terraform v1.5.0 and later, use an [`import` block](https://developer.hashicorp.com/terraform/language/import) instead:

```terraform
import {
  to = axonops_api_token.ci_readonly
  id = "6c0e8f5a-2b1d-4e7f-9a3c-1d2e3f4a5b6c"
}
```

> **Note:** an imported token has no `secret` in state, because AxonOps cannot return it again.
